# static-chafa - Developer Docs

## How it works

The build compiles chafa's source tree verbatim into `codec.so` / `static_chafa.node`. Chafa is never modified. Instead, a vendor layer sits in front of all its includes, replacing GLib, providing a fake autotools config, and stubbing unused sub-headers. The include path `-I vendor/chafa` is placed first so chafa's `#include <glib.h>` resolves to our replacement rather than the system's real GLib.

```
chafa source                 vendor layer                  our code
─────────────                ────────────                  ────────
internal/*.c                 vendor/chafa/                 src/codec.c
chafa-*.c      ──includes──► config.h      ──includes──►  src/addon.c
smolscale/*.c                glib_mini.h                   src/ffi.ts
                             chafa_quarks.c                src/index.ts
                             glib/*.h (stubs)
```

## Vendor files

| File | Role |
|------|------|
| `glib_mini.h` | Complete GLib replacement (~750 lines). Provides all types (`gint`, `guint`, `gboolean`, `GString`, `GHashTable`, `GArray`, `GQueue`, `GOnce`, `GMutex`, `GCond`, `GThread`, `GPollFD`, `GError`, `GUnicodeScript`, etc.), all macros (`MAX`, `MIN`, `CLAMP`, `g_new`, `g_return_if_fail`, `G_DEFINE_QUARK`, etc.), and all functions chafa calls (`g_malloc`, `g_free`, `g_strdup`, `g_string_*`, `g_hash_table_*`, `g_array_*`, `g_queue_*`, `g_thread_*`, `g_mutex_*`, `g_cond_*`, `g_poll`, `g_unichar_*`, `g_once_*`, `g_get_monotonic_time`, `g_environ_getenv`, `g_idle_add`, `g_source_remove`, etc.). |
| `glib.h` | Redirect - `#include "glib_mini.h"`. Placed in `-I vendor/chafa` so that chafa source's `#include <glib.h>` finds our replacement instead of the system GLib. |
| `config.h` | Fake autotools `config.h`. Sets version numbers (`CHAFA_MAJOR_VERSION`, etc.), `#undef`s all SIMD macros (`HAVE_AVX2_INTRINSICS`, `HAVE_SSE41_INTRINSICS`, etc.), defines `PACKAGE`/`VERSION` strings, and sets `WORDS_BIGENDIAN`. |
| `chafaconfig.h` | Version constants (`CHAFA_MAJOR_VERSION = 1`, etc.) - referenced by `chafa-version-macros.h`. |
| `chafa_quarks.c` | Provides `g_option_error_quark()` and `chafa_term_info_error_quark()`. These are normally generated by GLib's `G_DEFINE_QUARK` macro in each `.c` file, but since multiple `.c` files would produce duplicate symbols, we consolidate them here. |
| `glib-unix.h` | Stub header - chafa's `chafa-wakeup.c` and `chafa-stream-reader.c` include `<glib-unix.h>` for `g_unix_open_pipe`, `g_unix_set_fd_nonblocking`. The real implementations live in `glib_mini.h`; this file just exists so the `#include` doesn't fail. |
| `glib/gprintf.h` | Stub - chafa includes `<glib/gprintf.h>` for `g_vasprintf`. Impl in `glib_mini.h`. |
| `glib/gstdio.h` | Stub - chafa includes `<glib/gstdio.h>`. |

## What to do when chafa updates

| Chafa adds a new `.c` file | Add it to the `CHAFA_FILES` array in `build.sh` |
| Chafa adds a new `#include <glib/something.h>` | Create `vendor/chafa/glib/something.h` (empty stub is fine) |
| Chafa adds a new `#include <glib-something.h>` | Create `vendor/chafa/glib-something.h` (empty stub) |
| Chafa calls a new GLib function `g_foo()` | Add `g_foo()` implementation to `glib_mini.h` |
| Chafa checks a new `#ifdef HAVE_FOO` in config.h | Add `#undef HAVE_FOO` to `vendor/chafa/config.h` (or `#define` if you want it enabled) |
| Chafa adds a new quark (`G_DEFINE_QUARK(...)`) | Add a new function to `chafa_quarks.c` |
| Chafa adds a new `G_OPTION_ERROR_*` constant | Add to `glib_mini.h` |

The chafa source itself never gets patched - only the vendor layer expands.

## SIMD acceleration

Currently SIMD is disabled (`#undef HAVE_AVX2_INTRINSICS` etc. in `vendor/chafa/config.h`) for maximum portability. Chafa supports four ISAs with runtime dispatch:

| ISA | Files | Compiler flag | What it accelerates |
|-----|-------|---------------|---------------------|
| MMX | `chafa-mmx.c` | `-mmmx` | Mean color extraction |
| SSE4.1 | `chafa-sse41.c` | `-msse4.1` | Cell error calculation |
| POPCNT | `chafa-popcnt.c` | `-mpopcnt` | Population count / Hamming distance |
| AVX2 | `chafa-avx2.c`, `smolscale-avx2.c` | `-mavx2` | Cell error, mean colors, color division, image scaling |

All SIMD is dispatched at **runtime** via CPUID checks (`chafa_have_avx2()`, `chafa_have_sse41()`, etc.) - no compile-time target selection needed. The code falls back to pure C on unsupported CPUs.

### How to enable SIMD

**Critical:** Each SIMD `.c` file must be compiled as a separate translation unit with **only** its specific flag. The main code must NOT be compiled with `-mavx2` or the compiler will emit AVX2 instructions everywhere, crashing on non-AVX2 CPUs.

In `build.sh`, the approach would be to add a native-only block after the main chafa compilation loop:

```bash
# Only on native x86_64 (where the build machine IS the target)
if [ "${TARGET}" = "native" ]; then
    # Detect host CPU features
    if grep -q avx2 /proc/cpuinfo 2>/dev/null; then
        # Enable AVX2 + all lower ISAs
        CFLAGS="${CFLAGS} -DHAVE_AVX2_INTRINSICS -DHAVE_SSE41_INTRINSICS"
        CFLAGS="${CFLAGS} -DHAVE_MMX_INTRINSICS -DHAVE_POPCNT_INTRINSICS"
        CFLAGS="${CFLAGS} -DHAVE_POPCNT64_INTRINSICS"
        CFLAGS="${CFLAGS} -DHAVE_GCC_X86_FEATURE_BUILTINS"
        CFLAGS="${CFLAGS} -DSMOL_WITH_AVX2"

        # Compile SIMD files separately with their specific flags
        ${ZIG_CC} -c ${CFLAGS} -mavx2  ${INCLUDES} vendor/chafa-avx2.c -o ${OUTDIR}/chafa-avx2.o
        ${ZIG_CC} -c ${CFLAGS} -msse4.1 ${INCLUDES} vendor/chafa-sse41.c -o ${OUTDIR}/chafa-sse41.o
        ${ZIG_CC} -c ${CFLAGS} -mmmx ${INCLUDES} vendor/chafa-mmx.c -o ${OUTDIR}/chafa-mmx.o
        ${ZIG_CC} -c ${CFLAGS} -mpopcnt ${INCLUDES} vendor/chafa-popcnt.c -o ${OUTDIR}/chafa-popcnt.o
        ${ZIG_CC} -c ${CFLAGS} -mavx2 ${INCLUDES} vendor/smolscale-avx2.c -o ${OUTDIR}/smolscale-avx2.o

        OBJ_FILES="... ${OUTDIR}/chafa-avx2.o ${OUTDIR}/chafa-sse41.o ..."
    fi
fi
```

The vendor SIMD files would need to be copied from `/tmp/chafa_src/chafa/internal/` into `vendor/chafa/` (or the include paths extended).

For cross-compilation, you'd need to either:
- Detect the target's CPU features and set the `-m*` flags + defines accordingly
- Or just leave SIMD disabled (current behavior - safe, portable)

POPCNT is the easiest win - it's available on almost all x86_64 CPUs since 2008 and accelerates the Hamming distance calculations used heavily in symbol matching.
